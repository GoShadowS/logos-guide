# Конфигурация Android-сборки

Документ описывает инструментальную цепочку, варианты и выходные артефакты Android-модуля `:app`.

## Варианты приложения

`debug` предназначен для разработки и локального тестирования. Он имеет application ID suffix `.debug`, version suffix `-debug`, автоматически создаваемую debug-подпись и `OPEN_DOORS = false`.

`release` имеет `versionName = "1.1.0-release"`, `versionCode = 4` и `OPEN_DOORS = true`. Карточки пяти площадок Дня открытых дверей доступны в этом варианте. Минификация R8 отключена; конфигурация ProGuard сохраняет правила для моделей, обрабатываемых Gson.

Локальная подпись Release определяется конфигурацией Android Studio или Gradle-сборки. Keystore и его пароли не хранятся в репозитории. Workflow `.github/workflows/android-release.yml` собирает и публикует APK при отправке тега `v*`; он использует секреты репозитория `ANDROID_RELEASE_KEYSTORE_BASE64`, `ANDROID_RELEASE_KEYSTORE_PASSWORD`, `ANDROID_RELEASE_KEY_ALIAS` и `ANDROID_RELEASE_KEY_PASSWORD`. В release и workflow-сборках требуется один и тот же keystore. Задача `copyReleaseApk`, финализирующая `assembleRelease`, ищет APK в стандартном каталоге Gradle и в каталоге `app/release`, который может использовать мастер Android Studio. Самый новый найденный APK копируется в:

`app/build/outputs/apk/release/logos-guide-1.1.0-release.apk`

При одинаковом времени изменения приоритет отдаётся файлу, имя которого не содержит `unsigned`. Копирование не выполняет подпись: итоговая подпись соответствует исходному APK.

## Канал обновлений

Клиент обращается к публичному GitHub Releases API при запуске не чаще одного раза в сутки. Релиз публикуется под тегом `v<versionName>` и содержит APK `logos-guide-<versionName>.apk`. Модуль проверяет версию и имя артефакта, принимает только HTTPS-ссылку GitHub Releases, проверяет package ID и version name, затем передаёт APK Android Package Installer через FileProvider. В `1.0.0-opendoors` такого клиента нет, поэтому переход на `1.1.0-release` выполняется вручную один раз; авто-проверка доступна в `1.1.0-release` и следующих сборках.

Проверка и загрузка требуют интернета; карты, каталог и маршрутизация остаются локальными. Установка не может быть скрытой: Android требует разрешения на установку из этого источника и подтверждения пользователя. Подпись нового APK должна совпадать с подписью установленной версии. Публичные GitHub Releases и Actions образуют бесплатный канал распространения без оплаты магазина приложений.

## Архитектура и хранение

Пользовательский интерфейс реализован Compose-экранами и ViewModel. Состояние интерфейса передаётся через `StateFlow`; репозитории предоставляют данные каталога, навигации и избранного. Навигационные JSON-файлы и сгенерированная векторная карта поставляются внутри APK.

Настройки приложения хранятся в Preferences DataStore. Избранное, пользовательские папки, посещения, история и сохранённые маршруты размещаются в Room. Версия базы и миграции поддерживают перенос пользовательских данных между схемами; destructive migration не используется.

## Проверки сборки

Android CI включает unit tests, сборки Debug и Release, проверку версии и идентичности release APK, а также валидацию локальных данных. Для геометрических ресурсов используются Python-инструменты проекта, не требующие доступа Android-приложения к SVG во время выполнения.

Подробности формата `rooms.json` и `navigation_graph.json` приведены в [описании модели навигационных данных](JSON_DATA_GUIDE.md). Геометрические исходники и соответствие SVG/Kotlin-карты описаны в [документе по картам этажей](SVG_MAPPING_RU.md).
