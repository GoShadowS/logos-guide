# Подробная инструкция: от проекта до APK

Руководство рассчитано на человека, который раньше не собирал Android-приложения. В проекте уже есть исходники, настройки Gradle, ресурсы и JSON. **Создавать пустой новый проект и переносить код вручную не нужно** — откройте существующую папку.

## Что понадобится

- компьютер под Windows 10/11, macOS или Linux;
- желательно **16 ГБ оперативной памяти** (Android Studio запускается и на 8 ГБ, но эмулятор может работать медленно);
- около **15–25 ГБ свободного места** для Android Studio, SDK, Gradle-кэша и системного образа эмулятора;
- интернет для первоначальной загрузки IDE/SDK/Gradle/зависимостей. После установки APK карты и каталог работают офлайн;
- Android-телефон Android 7.0/API 24 или новее — или эмулятор.

В проекте выставлено: `minSdk = 24`, `targetSdk = 36`, `compileSdk = 37`, JVM bytecode target 17, Android Gradle Plugin 9.3.1, Gradle 9.7.0, Kotlin 2.4.21 и KSP 2.3.12. Для сборки нужен JDK 25. Android 8 (API 26) остаётся поддерживаемой версией. Приложение не объявляет разрешение INTERNET; карты, поиск и маршруты работают офлайн. Карточки Дня открытых дверей включены только в release `1.0.0-opendoors`.

## 1. Скачать и установить Android Studio

1. Откройте официальный сайт: **https://developer.android.com/studio**.
2. Нажмите **Download Android Studio**.
3. Прочитайте условия, отметьте согласие и скачайте установщик для своей ОС.
4. Запустите скачанный файл.
   - **Windows:** оставьте отмеченными Android Studio и Android Virtual Device, если мастер установки предлагает такой выбор. Нажимайте **Next → Install → Finish**.
   - **macOS:** откройте `.dmg` и перетащите Android Studio в папку `Applications`.
   - **Linux:** распакуйте архив в удобное место и запустите `bin/studio.sh`.
5. При первом открытии выберите стандартный вариант **Standard setup**. Если будет предложено принять лицензии Android SDK, нажмите **Accept** для каждой и дождитесь завершения загрузки.
6. Не закрывайте Android Studio, пока первоначальная настройка устанавливает Android SDK и необходимые компоненты.

Если установщик предлагает импортировать старые настройки, для первого запуска можно выбрать **Do not import settings**.

## 2. JDK: что установить и как проверить

Android Studio поставляется со встроенным Java Runtime/Java Development Kit. Для этого проекта нужен **JDK 25**. Отдельная установка обычно не требуется.

Проверить или указать встроенный JDK:

1. Откройте Android Studio.
2. Windows/Linux: выберите **File → Settings**. На macOS: **Android Studio → Settings**.
3. В левой колонке откройте **Build, Execution, Deployment → Build Tools → Gradle**.
4. Найдите поле **Gradle JDK** и выберите вариант с надписью **Embedded JDK** / **jbr-25** / **25**.
5. Нажмите **Apply**, затем **OK**.

Если встроенного JDK нет, установите Temurin 25 с сайта **https://adoptium.net/temurin/releases/?version=25** (выберите свою ОС, архитектуру и JDK 25), затем в поле **Gradle JDK** нажмите **Add JDK…** и укажите папку установленной JDK. Не выбирайте JRE — нужен именно JDK.

## 3. Android SDK: какие компоненты выбрать

При первоначальной настройке Android Studio может поставить часть компонентов автоматически. Если проект сообщает, что SDK отсутствует, установите его вручную:

1. На стартовом окне нажмите **More Actions → SDK Manager**. Если проект уже открыт: **Tools → SDK Manager**. На некоторых версиях Android Studio ссылка находится в **File → Settings → Languages & Frameworks → Android SDK**.
2. Вкладка **SDK Platforms**:
   - отметьте **Android 17 — API Level 37**;
   - нажмите **Apply**.
3. Вкладка **SDK Tools** отметьте:
   - **Android SDK Build-Tools 37.0.0** (если строка показывает несколько версий — раскройте список и выберите `37.0.0`);
   - **Android SDK Platform-Tools**;
   - **Android SDK Command-line Tools (latest)**;
   - **Android Emulator**;
   - **Google USB Driver** — только Windows, если будете подключать устройство и драйвер не установлен.
4. Нажмите **Apply → OK**, примите лицензии и дождитесь окончания установки.
5. Вверху окна SDK Manager найдите **Android SDK Location** — запишите этот путь. Типовые пути:
   - Windows: `C:\Users\<имя>\AppData\Local\Android\Sdk`;
   - macOS: `/Users/<имя>/Library/Android/sdk`;
   - Linux: `/home/<имя>/Android/Sdk`.

Проект использует Gradle Wrapper и сам запрашивает указанные версии. Не устанавливайте случайную устаревшую версию Gradle в систему.

## 4. Открыть существующий проект

1. Распакуйте/склонируйте репозиторий в папку, путь к которой не содержит необычных символов. Например, `C:\Projects\logos-guide` или `~/Projects/logos-guide`.
2. Запустите Android Studio.
3. На стартовом экране нажмите **Open**. Если уже открыт другой проект: **File → Open…**.
4. Выберите папку проекта `logos-guide` — именно ту, где лежат `settings.gradle.kts`, `build.gradle.kts`, `gradlew` и папка `app`. Не выбирайте `app/src` и не выбирайте отдельный Kotlin-файл.
5. Подтвердите открытие проекта в новом окне, если Android Studio спросит.
6. Если появится уведомление **Trust Project?**, выберите **Trust Project** для проверенной копии проекта.
7. Дождитесь первичной индексации файлов и синхронизации Gradle. При первом открытии Gradle загружает свои компоненты и зависимости, поэтому это может занять несколько минут.

Не создавайте второй Empty Activity: проект уже содержит `MainActivity`, Gradle-конфигурацию и Compose UI.

## 5. Где лежат исходники и куда класть карты

Ключевые части проекта:

```text
settings.gradle.kts                         # имя проекта и модуль :app
build.gradle.kts                            # версии плагинов Android/Kotlin
app/build.gradle.kts                        # SDK, версия приложения и библиотеки
app/src/main/AndroidManifest.xml            # приложение, стартовая Activity, разрешения
app/src/main/java/com/logos/navigator/      # весь Kotlin-код
app/src/main/assets/navigation_graph.json   # этажи, SVG viewBox, узлы, GPS-якоря, рёбра
app/src/main/assets/rooms.json              # локальный каталог
app/src/main/assets/floors/floor_1.svg      # единственная карта 1-го этажа
app/src/main/assets/floors/floor_2.svg      # единственная карта 2-го этажа
app/src/main/res/drawable-nodpi/logo.png
app/src/main/res/drawable-nodpi/splash_screen.png
app/src/main/res/drawable/ic_restroom_24.xml # VectorDrawable быстрых действий
app/src/main/res/drawable/ic_stairs_24.xml   # VectorDrawable быстрых действий
app/schemas/                                # экспорт схем Room (после Gradle-сборки)
app/src/main/res/values/                     # RU строки, цвета и темы окна
app/src/main/res/values-en/                  # EN строки
```

Из исходной `maps_and_design` в репозитории уже скопированы планы этажей и графические материалы:

- `map1lower.svg` → `app/src/main/assets/floors/floor_1.svg`;
- `map2lower.svg` → `app/src/main/assets/floors/floor_2.svg`;
- `map1lower_cabinet.png` и `map2lower_cabinet.png` остаются только в `maps_and_design/` как справочные растровые планы; в APK они не копируются и не рендерятся;
- `maps_and_design/logo.png` → `app/src/main/res/drawable-nodpi/logo.png` (та же PNG используется в иконке приложения, приветственном экране онбординга, шапке карты и разделе «О приложении»);
- `splash.png` → `app/src/main/res/drawable-nodpi/splash_screen.png`.

Если заменяете SVG-карту, сохраните `.svg`, обновите `mapAsset`, `viewBoxX`, `viewBoxY`, `width` и `height` в `navigation_graph.json`, затем заново проверьте координаты узлов, комнат и GPS-якорей. Для планов текущие viewBox — `0 0 758 552` и `0 0 767 561`. Не экспортируйте план в PNG. Ресурсы в `res` должны быть названы латиницей, строчными буквами, без пробелов; например `logo.png`. Пошаговый гайд измерения SVG-координат: [`JSON_DATA_GUIDE.md`](JSON_DATA_GUIDE.md).

XML layout в `res/layout` отсутствуют намеренно: пользовательский интерфейс создан с Jetpack Compose. Остальные Android XML — `AndroidManifest.xml`, темы/цвета/строки и адаптивная иконка.

## 6. Синхронизация Gradle

Обычно Android Studio запускает Sync после открытия. Если нет:

1. Выберите **File → Sync Project with Gradle Files** (на macOS пункт File такой же).
2. Дождитесь сообщения **BUILD SUCCESSFUL** или окончания Gradle Sync в нижней панели **Build**.
3. Если справа/сверху появилось **Sync Now**, нажмите его.
4. Убедитесь, что Gradle JDK выбран как 25 (см. шаг 2), а SDK Platform 37 и Build-Tools 37.0.0 установлены (шаг 3).
5. Если зависимость не скачалась, проверьте подключение к интернету и повторите **Sync Project with Gradle Files**. Для первого Sync нужны доступные Google Maven и Maven Central.
6. Откройте вкладку **Build** внизу. Первая красная строка и блок **Caused by** обычно указывают первопричину, а не последнюю строку ошибки.

Не удаляйте файлы проекта и не меняйте версии Gradle/плагинов вручную: согласованные версии указаны в `build.gradle.kts`, `app/build.gradle.kts` и `gradle/wrapper/gradle-wrapper.properties`. При ошибке сначала проверьте JDK, интернет, SDK и путь к проекту.

## 7. Подключить телефон или создать эмулятор

### Физический Android-телефон

1. На телефоне откройте **Настройки → О телефоне**.
2. Найдите **Номер сборки** и нажмите по нему 7 раз. Введите PIN/пароль, если система попросит. Появится сообщение о режиме разработчика.
3. Вернитесь в настройки и откройте **Для разработчиков** (иногда **Система → Для разработчиков**).
4. Включите **Отладка по USB**. Подтвердите предупреждение.
5. Соедините телефон USB-кабелем передачи данных. В уведомлении USB выберите режим передачи файлов, если телефон его предлагает.
6. На экране телефона подтвердите диалог **Разрешить USB-отладку?** и при личном компьютере можно поставить **Всегда разрешать с этого компьютера**.
7. В Windows установите USB-драйвер производителя или Google USB Driver из SDK Manager. На macOS отдельный драйвер обычно не требуется; Linux может потребовать правило udev.
8. В Android Studio в верхнем списке устройств должно появиться имя телефона. Если его нет, переподключите кабель, подтвердите RSA-диалог, проверьте драйвер и выполните **Tools → Troubleshoot Device Connections** (если доступно).

### Эмулятор (AVD)

1. Откройте **Tools → Device Manager** (в старых сборках: **Tools → AVD Manager**).
2. Нажмите **Create Device**.
3. Выберите, например, **Pixel 6** или **Pixel 7** → **Next**.
4. В списке System Image выберите **Android 17 / API 37 / Google Play / x86_64** и нажмите **Download**. Google Play-образ предпочтительнее для проверки Fused Location Provider; если он недоступен, используйте доступный образ и тестируйте ручной режим. Для проверки минимальной поддержки отдельно запустите Android 8 / API 26.
5. Нажмите **Next**. В **Verify Configuration** оставьте портретный режим; выделите 2–4 ГБ RAM, если компьютер имеет минимум 16 ГБ (при 8 ГБ задайте 2 ГБ и закройте тяжёлые приложения).
6. Нажмите **Finish**, затем кнопку запуска ▶ напротив созданного виртуального устройства.
7. Для GPS на эмуляторе нажмите `⋮` → **Location**, введите координаты или выберите точку на карте, нажмите **Set Location**. Помните, это тест внешнего GPS-положения, а не фактического определения этажа.

## 8. Запустить приложение

1. Дождитесь, пока эмулятор полностью загрузит Android, или подключите телефон.
2. В Android Studio в верхней панели выберите конфигурацию **app** и своё устройство.
3. Нажмите зелёный треугольник **Run ▶** или клавиши **Shift+F10** (Windows/Linux; на macOS сочетание может отличаться).
4. При вопросе о USB-отладке подтвердите запуск.
5. После установки откроется приложение с заставкой, затем карта. Сначала выберите **Вручную** и нажмите точку на карте; для поиска откройте значок лупы или каталог. Для GPS отдельно переключитесь на **GPS** и разрешите доступ только при запросе.
6. Для тестирования межэтажного маршрута отметьте положение в доступной зоне, выберите помещение другого этажа и проверьте шаги лестницы. По умолчанию используется лестница; доступный лифт включается существующей опцией онбординга/настроек. Точки и веса графа хранятся в системе координат SVG `viewBox`, но двери и коридорные связи предварительные до полевой проверки. Серая зона актового зала второго этажа закрыта: маршрут оттуда не начинается и узлы внутри неё отсутствуют.

## 9. Собрать Release APK с подписью

APK для распространения должен быть подписан. Хранилище ключей (keystore) создаётся один раз. **Не отправляйте keystore и пароли в чат/репозиторий и сделайте резервную копию в безопасном месте.** Потеря ключа означает, что обновить приложение с тем же Android application ID будет сложно/невозможно.

1. В верхнем меню выберите **Build → Generate Signed Bundle / APK…**.
2. В появившемся мастере выберите **APK** (не Android App Bundle) → **Next**.
3. На экране подписи нажмите **Create new…** рядом с **Key store path**.
4. Выберите безопасное место, например отдельную папку `Documents/AndroidKeys/logos-release.jks`. Не кладите ключ в `app/` и тем более не добавляйте в Git.
5. Заполните поля:
   - **Password** — пароль keystore; запишите в менеджер паролей;
   - **Confirm** — повтор пароля;
   - **Key alias** — например `logos_release` (запомните регистр и написание);
   - **Key password** и подтверждение — пароль ключа (можно использовать тот же сильный пароль, если мастер допускает);
   - **Validity (years)** — например `30` (минимальный рекомендуемый срок для долгой поддержки — не менее 25 лет);
   - **First and Last Name**, **Organizational Unit**, **Organization**, **City or Locality**, **State or Province**, **Country Code** — заполните данными владельца/организации; код страны обычно две латинские буквы.
6. Нажмите **OK**. Проверьте путь и alias и нажмите **Next**.
7. В поле **Build Variant** выберите **release**. В нём отображаются карточки пяти площадок Дня открытых дверей, встроенные в приложение. Имя релизной версии — `1.0.0-opendoors` (код версии 3). Для этих инструкций достаточно оставить выбранными назначение `V1` и `V2` подписи, если мастер показывает эти флажки.
8. Нажмите **Create** / **Finish**. В панели Build дождитесь **BUILD SUCCESSFUL**; после успешной сборки Android Studio покажет ссылку **locate**.
9. Release-вариант сохраняет `versionName = "1.0.0-opendoors"`. Имя APK-файла: `logos-guide-1.0.0-opendoors.apk`; полный путь:
   `app/build/outputs/apk/release/logos-guide-1.0.0-opendoors.apk`
   Задача `assembleRelease` автоматически создаёт это имя для собранного APK.
10. Передайте на устройство именно `logos-guide-1.0.0-opendoors.apk` и храните release APK вместе с информацией о версии. Keystore — отдельно.

Если пункт Build называется немного иначе в установленной версии Android Studio, ищите **Generate Signed Bundle / APK** в меню **Build**. Не выбирайте **Bundle**, если нужен именно APK-файл для ручной установки.

## 10. Установить APK на телефон

1. Передайте `app-release.apk` на телефон USB-кабелем, через локальную передачу файлов или другой выбранный вами способ. Не публикуйте закрытый APK/данные, если они предназначены только сотрудникам колледжа.
2. На телефоне откройте приложение **Файлы** и найдите APK в папке **Загрузки** или выбранном месте.
3. Нажмите APK. Android может показать блокировку установки из неизвестного источника.
4. Нажмите **Настройки** в предупреждении и включите **Разрешить установку из этого источника** для приложения, которым открываете файл (например, «Файлы» или браузера). На разных телефонах путь выглядит как **Настройки → Приложения → Специальный доступ → Установка неизвестных приложений**.
5. Вернитесь назад, нажмите **Установить**, затем **Открыть**.
6. Для безопасности после установки можно снова отключить разрешение **Разрешить установку из этого источника**.

Если Android пишет «Приложение не установлено», проверьте свободное место, версию Android (не ниже 7.0), целостность передачи APK и установленную ранее версию. Debug-сборка имеет суффикс `.debug` и может сосуществовать с release, потому что у неё другой application ID.

## 11. Собрать Debug APK без release-keystore

Debug-сборка подписывается автоматически тестовым ключом Android Gradle Plugin:

1. Выберите **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
2. Дождитесь **BUILD SUCCESSFUL**.
3. Нажмите **locate** в уведомлении или откройте:
   `app/build/outputs/apk/debug/app-debug.apk`
4. Этот APK предназначен для отладки/проверки, не для публикации как release; карточки Дня открытых дверей в debug отключены. Разрешение на установку из неизвестных источников может понадобиться и для него.

Из терминала, если `adb` доступен в Android SDK Platform-Tools:

```bash
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

На Windows вместо `./gradlew` используйте `gradlew.bat`.

## 12. Частые ошибки и решения

### `SDK not found`, `SDK location not found`

1. Откройте **Tools → SDK Manager** и посмотрите поле **Android SDK Location**.
2. Убедитесь, что там установлены API 37 и Build-Tools 37.0.0.
3. Если проект скопирован на другой компьютер, создайте в корне локальный файл `local.properties` (он персонален для компьютера и не должен попадать в Git):

   ```properties
   sdk.dir=C\:\\Users\\ИМЯ\\AppData\\Local\\Android\\Sdk
   ```

   Для macOS пример: `sdk.dir=/Users/ИМЯ/Library/Android/sdk`. Проще всего скопировать путь из SDK Manager и использовать прямые слеши `/`. Перезапустите **Sync Project with Gradle Files**.

### `Gradle sync failed`, Gradle/JDK несовместимы

1. В **Settings → Build, Execution, Deployment → Build Tools → Gradle** задайте **Gradle JDK = Embedded JDK 25**.
2. Проверьте, что интернет доступен и Gradle не работает в Offline mode: в окне Gradle выключите **Toggle Offline Mode**.
3. Нажмите **File → Sync Project with Gradle Files**.
4. Если кэш явно повреждён, закройте Android Studio и удалите только каталог пользовательского Gradle-кэша (`~/.gradle/caches`; на Windows `%USERPROFILE%\.gradle\caches`), затем откройте проект и повторите Sync. Повторная загрузка зависимостей займёт время.
5. В крайнем случае выберите **File → Invalidate Caches… → Invalidate and Restart**. Это перестроит индекс Android Studio, но не удалит исходный код.
6. Не обновляйте Gradle Wrapper и Android Gradle Plugin произвольно. Согласованные версии записаны в корневом `build.gradle.kts` и `gradle/wrapper/gradle-wrapper.properties`.

### `Minimum SDK ...`, приложение не устанавливается

Устройство должно иметь Android **7.0/API 24 или новее**. В проекте `minSdk = 24`. Старые устройства не поддерживаются. Для проверки откройте **app/build.gradle.kts → defaultConfig** и убедитесь, что значение не изменено случайно.

### `Duplicate class`

1. Посмотрите в Build Output, какие именно классы и две зависимости их приносят.
2. Не добавляйте вручную старую библиотеку Android Support рядом с AndroidX. Проект использует AndroidX.
3. Не вставляйте повторно зависимости Compose, Gson или Google Location Services в `app/build.gradle.kts`.
4. Выполните **File → Sync Project with Gradle Files**, затем **Build → Clean Project** и **Build → Rebuild Project**.
5. Исключайте транзитивную зависимость только если точно понимаете, какая библиотека дублируется; случайные `exclude` могут сломать сборку.

### `OutOfMemoryError` во время сборки

1. Закройте тяжёлые приложения и лишние Android-эмуляторы. Сам эмулятор использует значительный объём ОЗУ.
2. В корневом `gradle.properties` по умолчанию установлен `-Xmx3g`, чтобы оставить память IDE и эмулятору. Если у компьютера не меньше 16 ГБ RAM и сборка всё ещё завершается ошибкой нехватки памяти, можно попробовать `-Xmx4g` или `-Xmx6g`; при 8 ГБ оставьте 3 ГБ и не запускайте одновременно несколько AVD.
3. В **Settings → Build, Execution, Deployment → Compiler** проверьте настройки параллельной сборки. При нехватке RAM отключите параллельную сборку параметром `org.gradle.parallel=false` в `gradle.properties`.
4. Перезапустите Android Studio и повторите сборку. Не устанавливайте `android:largeHeap` для борьбы с ошибкой компиляции — это не меняет память Gradle.

### Не загружается карта/маркер находится не в том месте

- Убедитесь, что `mapAsset` указывает на эталонный `.svg` в `app/src/main/assets/floors/`, а папка не содержит растровых планов.
- Сверьте `viewBoxX`, `viewBoxY`, `width` и `height` с исходным `viewBox`, заново проверьте `x/y` всех узлов, комнат и GPS-якорей.
- Выполните `python3 tools/generate_kotlin_floor_maps.py --check`. Если меняли SVG, сначала перегенерируйте `GeneratedFloorMaps.kt`; неподдерживаемые генератором конструкции должны быть исправлены в исходнике.
- JSON-файлы должны быть валидными; в сообщении приложения есть имя проблемного файла/поля.
- `navigation_graph.json` и `rooms.json` находятся в `app/src/main/assets/`, не в `res/drawable`.
- Фактическую GPS-привязку сначала проверьте на нескольких точках. В помещении переключайтесь на «Вручную», если положение плавает или оценка accuracy выше 20 м.

## 13. Локальные настройки и пользовательская база Room

Настройки Appearance/Map/Navigation/Location/Favorites/History хранятся в Preferences DataStore; изменения сразу обновляют Compose StateFlow и сохраняются локально. Избранные помещения, пользовательские папки, посещения, история и сохранённые маршруты хранятся в `logos_favorites.db` через Room. JSON-резервная копия включает категории, избранное, историю и сохранённые маршруты.

Если структура Entity меняется:

1. Увеличьте `version` в `@Database` в `AppDatabase.kt`.
2. Создайте явный объект `Migration(oldVersion, newVersion)` с SQL, сохраняющим старые поля и пользовательские данные.
3. Добавьте миграцию через `.addMigrations(...)` в `Room.databaseBuilder`; не добавляйте `fallbackToDestructiveMigration()`.
4. Соберите проект, чтобы Room/KAPT сформировал актуальную JSON-схему в `app/schemas/`; сохраните её в репозитории вместе с миграцией.
5. Протестируйте обновление реальной старой базы, проверив избранное, папки, историю и маршруты. Проверяйте уникальные индексы и значения `NULL` в SQL.

Для Preferences DataStore добавляйте новые ключи с безопасными значениями по умолчанию и обновляйте преобразование `Preferences → AppSettings` и обратную запись. `resetToDefaults()` не должен удалять Room-базу.

## 14. Release, R8 и ProGuard

В текущем проекте release-настройка имеет `isMinifyEnabled = false`; это уменьшает риск удалить модели JSON или классы, используемые библиотеками через reflection. Для обычной установки release APK сначала достаточно мастера **Build → Generate Signed Bundle / APK…** из шага 9.

Если организация включает R8:

1. Установите `isMinifyEnabled = true` только после отдельной тестовой сборки.
2. Проверьте `app/proguard-rules.pro`: модели `com.logos.navigator.data.model` сохраняются для Gson; сохраняются generic signatures/аннотации. Удалите только ставшие ненужными правила библиотек после проверки зависимостей.
3. Соберите `./gradlew assembleRelease` и установите release APK на тестовое устройство.
4. Проверьте чтение обоих JSON, миграцию Room, импорт/экспорт резервной копии, открытие обеих Canvas-карт, поиск и подсветку помещений, а также построение маршрута.
5. Если R8 переименовал поля Gson, добавьте явные `@SerializedName` либо точечные keep-правила и повторите тест.

Не отключайте предупреждения/проверки массовыми `-dontwarn` без понимания причины. Не добавляйте в репозиторий signing keystore или пароли; release signature и ключ храните отдельно.

## 15. Оптимизация исходных SVG и сгенерированной карты

Android отрисовывает план нативными Kotlin `Canvas`/`Path`-командами из `GeneratedFloorMaps.kt`; SVG остаётся редактируемым эталоном. Перед генерацией удаляйте только действительно невидимые редакторские слои, метаданные и вложенные изображения, упрощайте избыточные path-команды без изменения геометрии, сохраняйте ID комнат и порядок слоёв. Не заменяйте векторный план растровым PNG ради скорости.

Папка `app/src/main/assets/floors/` содержит только два эталонных SVG; приложение не парсит их при запуске. Не добавляйте туда PNG-планы и ненужные референсы. Логотип/заставка хранятся отдельно в `drawable-nodpi`. Большие исходные JPG/PNG для сверки оставляйте в `maps_and_design/`, не копируйте их как runtime-карты.

После изменения SVG запустите `python3 tools/generate_kotlin_floor_maps.py`, затем проверьте актуальность `python3 tools/generate_kotlin_floor_maps.py --check` и данные `python3 tools/validate_indoor_data.py`. Не меняйте ID и `viewBox` без синхронной проверки `rooms.json` и `navigation_graph.json`; сравните сгенерированные карты с эталоном в Android Studio и на устройстве.
