# Карты SVG, координаты, граф и каталог помещений

Это руководство относится к Android-приложению «Логос». Все маршрутизируемые данные работают офлайн.

## 1. Что помещать в приложение

Планы этажей в APK берутся **только из предоставленных SVG**:

| Исходник | Ресурс приложения | viewBox |
|---|---|---|
| `maps_and_design/map1lower.svg` | `app/src/main/assets/floors/floor_1.svg` | `0 0 758 552` |
| `maps_and_design/map2lower.svg` | `app/src/main/assets/floors/floor_2.svg` | `0 0 767 561` |

Планы `map1lower_cabinet.png` и `map2lower_cabinet.png` остаются в `maps_and_design/` только как справочные изображения для изучения планировки. **Не копируйте растровые планы в `app/src/main/assets/floors/`, не меняйте карту на PNG и не рендерьте растровый план в Android.** Папка `assets/floors/` должна содержать только SVG-карты. PNG логотипа и заставки — отдельные разрешённые ресурсы `res/drawable-nodpi/`.

В `app/src/main/assets/` находятся два файла данных:

- `navigation_graph.json` — этажи, GPS-якоря, узлы графа и рёбра;
- `rooms.json` — каталог помещений и маркеры.

Текущий набор содержит 100 узлов, 104 ребра, 8 GPS-якорей и 47 записей каталога: 30 физических помещений из авторитетного списка (34 номера, так как 141/142/147/159/160 объединены одной записью) и 17 вспомогательных зон. Граф содержит только узлы и рёбра реально предполагаемых проходов; наличие контура в `rooms.json` само по себе не делает помещение проходимым. Например, помещение 104 — зона актового зала на первом этаже: её SVG-контур сохранён для отображения, но `route_available` отключён, `nodeId` и дверные узлы отсутствуют, а сама зона не является узлом или проходом графа. На втором этаже серая зона актового зала/смотровой и другие закрытые области также запрещены для маршрутизации. Дополнительные узлы делят только ранее заданные прямые участки коридоров; спорный прямой участок через кабинет 202 удалён, а подход к лифту 1-го этажа проведён через отдельную точку коридора. Валидатор проверяет, что рёбра коридоров не пересекают геометрию кабинетов; частичное совпадение контура кабинета 149 с лестницей оставлено как явное исключение и требует полевой проверки. Помещения 144, 161, 232 и 233 пока не маршрутизируются, потому что их точные SVG-контуры и входы не подтверждены.

## 2. Что такое `viewBox` и какие координаты хранить

У SVG есть пользовательская система координат, заданная атрибутом корневого элемента:

```xml
<svg width="758" height="552" viewBox="0 0 758 552" ...>
```

Формат атрибута: `viewBox="minX minY width height"`. Начало (0,0) обычно находится в верхнем левом углу, x растёт вправо, y — вниз. **`x/y` в JSON записываются в единицах этой системы SVG**, а не в координатах PNG, экрана телефона или dp.

Для текущих файлов границы такие:

- этаж 1: `x = 0…758`, `y = 0…552`;
- этаж 2: `x = 0…767`, `y = 0…561`.

В `navigation_graph.json` у этажа `width` и `height` равны третьему и четвёртому числам `viewBox`; `viewBoxX` и `viewBoxY` равны первым двум. Если новый SVG имеет, например, `viewBox="12 8 800 600"`, у этажа должны быть `viewBoxX: 12`, `viewBoxY: 8`, `width: 800`, `height: 600`, а координаты следует брать в диапазонах `x = 12…812`, `y = 8…608`.

Поле `metersPerUnit` — приближённый перевод одной SVG-единицы в метры. Текущие значения (`0.08332894` и `0.08334442`) были перенесены вместе с координатами из предыдущей растровой привязки и являются **предварительными**. Для реального расстояния измерьте известный отрезок на месте/плане и откалибруйте масштаб заново.

## 3. Пошаговая подготовка SVG и ID помещений

### 3.1. Сделайте рабочую копию и зафиксируйте `viewBox`

1. Не изменяйте исходники в `maps_and_design/` напрямую. Создайте рабочую копию SVG.
2. Откройте её в Inkscape. В свойствах документа проверьте страницу и `viewBox`; не обрезайте, не масштабируйте и не поворачивайте весь план после измерения координат.
3. Сохраните заметку: `minX`, `minY`, `width`, `height` из `viewBox` и имя файла.
4. Скопируйте окончательный файл в `app/src/main/assets/floors/floor_N.svg`; проверьте, что в `navigation_graph.json` указан именно этот путь и точные размеры viewBox.

### 3.2. Назначьте ID

ID удобны для выделения назначения и автоматизированного поиска bbox, но не обязательны для обычного рендеринга.

1. В Inkscape выберите геометрию, соответствующую помещению (контур/прямоугольник комнаты, а не текст подписи).
2. Откройте **Object → Objects…** или **Edit → XML Editor** (название зависит от версии Inkscape).
3. Задайте стабильный уникальный ID латиницей, без пробелов и `#`, например `room_101`, `room_lab_2` или `stairs_west_f1`.
4. Сохраните файл и проверьте исходный XML: целевой элемент должен выглядеть примерно так: `<rect id="room_101" ... />`.
5. Не используйте один и тот же ID для нескольких элементов. Не используйте только номер кабинета для двухэтажных одинаковых кабинетов — добавьте префикс этажа.
6. Для одного контура добавьте ID в `rooms.json.svgElementId`; для нескольких контуров — в `svgElementIds` и сохраните их координаты как отдельные списки в `polygons`. AndroidSVG подсветит все связанные элементы. Для входа укажите `doorNodeId`/`doorNodeIds`; графовый `nodeId` должен вести к узлу на доступной стороне коридора. Если геометрия не подтверждена, используйте `route_available: false`, `nodeId: null`, `x: null`, `y: null` и поясняющий `geometry_status` — не придумывайте координаты.

### 3.3. Снимите центр и bounding box элемента по ID

Для автоматического извлечения используйте `tools/extract_svg_geometry.py`. Он читает ID у `<rect>`, `<polygon>` и закрытых `<path>`, учитывает вложенные SVG `transform` и выводит вершины в корневой системе координат `viewBox`. Кривые Безье аппроксимируются отрезками для проверки; в `rooms.json` храните отдельные проверенные контуры, а не считайте аппроксимацию полевым измерением.

```bash
python3 tools/extract_svg_geometry.py app/src/main/assets/floors/floor_2.svg --strict
```

Скрипт принимает `--prefix room_`, `--prefix door_` и `--prefix restricted_` (можно повторять `--prefix`), а `--strict` завершает проверку с ошибкой, если координаты выходят за `viewBox`.

**Опционально — браузерная проверка ID и bbox:**

1. Откройте отдельный SVG-файл напрямую в современном браузере.
2. Откройте DevTools → Console.
3. Выполните пример ниже, заменив `room_101` на ID элемента:

```javascript
const svg = document.documentElement;
const element = svg.getElementById('room_101');
if (!element) throw new Error('ID не найден');
const box = element.getBBox();
const rootToScreen = svg.getScreenCTM();
const elementToRoot = rootToScreen.inverse().multiply(element.getScreenCTM());
const center = new DOMPoint(box.x + box.width / 2, box.y + box.height / 2)
  .matrixTransform(elementToRoot);
console.log({ x: center.x, y: center.y, localBBox: box });
```

`center.x/center.y` — центр элемента, переведённый в координаты корневого SVG, подходящие для JSON. `getBBox()` возвращает локальный bounding box; `elementToRoot` учитывает вложенные трансформации для центра. Для bbox повёрнутых элементов преобразуйте все четыре угла `box` через ту же матрицу и пересчитайте min/max. Проверьте результаты визуально: SVG может использовать CSS, маски или сложные трансформации, которые не сводятся к прямоугольнику.

Для обычных комнат предпочтительно брать геометрический центр контура/прямоугольника. Если контур длинный/неправильный, выберите вручную удобную внутреннюю точку. Маркер не обязан совпадать с маршрутизируемой дверью: дверь задаётся отдельно через ближайший узел `nodeId` у коридора.

## 4. Как измерять координаты узлов и помещений

Для каждого значения храните таблицу проверки: этаж, ID, x, y, источник измерения, комментарий.

1. Измеряйте на финальном SVG — в Inkscape или через приведённый выше браузерный DOM — не по уменьшенному скриншоту/PNG.
2. Для графа размещайте узел на реально доступной стороне дверного проёма, в центре коридора, холла, перекрёстка или площадки у лифта/лестницы. Не ставьте его в толщу стены.
3. Добавляйте узел на поворотах и разветвлениях. Один длинный прямой коридор не нужно разбивать на множество произвольных точек.
4. Маркер помещения (`x/y` в `rooms.json`) ставьте внутри помещения; `nodeId` должен вести к доступному проходу/двери на том же этаже.
5. Проверяйте границы: все координаты узлов, GPS-якорей и помещений должны находиться внутри соответствующего viewBox.
6. После правки откройте карту на Android и сравните реальные оверлеи с планом. Если SVG заменён, координаты следует снять заново.

### Обязательное полевое предупреждение: узел `1_01`

Точка `1_01` у главного входа в текущем JSON имеет предварительные координаты `x: 576.54`, `y: 240.96` в viewBox 1-го этажа. **Обязательно проверьте на месте, что проход там открыт и узел не попадает на стену/закрытую дверь.** Если проход непроходим, перенесите `x/y` `1_01` на ближайшую доступную точку порога/коридора, проверьте связь и вес ребра `1_01`—`1_02`, затем пройдите маршрут от входа к соседним помещениям. Сохраняйте ID `1_01`, если возможно; при изменении ID обновите `rooms.json.nodeId` и все рёбра, ссылающиеся на этот узел.

## 5. `navigation_graph.json`

`navigation_graph.json` — взвешенный граф проходимых коридоров и межэтажных переходов. Только узлы из `nodes` и связи из `edges` участвуют в поиске маршрута; контуры и маркеры из `rooms.json` служат для каталога и отображения. Маршрут строится A* от стартового узла к `rooms.json.nodeId`. Приложение также рисует прямые соединители от текущей точки до первого узла и от последнего узла к маркеру помещения; их геометрия не является отдельной проверенной связью графа, поэтому положение входов и такие участки необходимо сверять с SVG и на месте.

Вес ребра задаётся в приблизительных метрах и описывает длину участка. Настройки «избегать лестниц»/«избегать лифт» могут менять стоимость выбора пути, но не физическую длину, показываемую пользователю. По умолчанию рёбра лифта исключены. Доступный режим включается пользователем: он разрешает лифтовые рёбра и, если для той же пары этажей есть этот лифт, исключает соответствующее лестничное ребро. Геометрия и веса остаются предварительными до проверки в здании.

Минимальный пример структуры:

```json
{
  "floors": [
    {
      "number": 1,
      "title": "1 этаж",
      "mapAsset": "floors/floor_1.svg",
      "width": 758,
      "height": 552,
      "viewBoxX": 0,
      "viewBoxY": 0,
      "metersPerUnit": 0.08332894
    }
  ],
  "gpsAnchors": [
    { "floor": 1, "id": "anchor_a", "lat": 55.215005, "lon": 36.537568, "x": 120.5, "y": 90.25 }
  ],
  "nodes": [
    { "id": "1_01", "floor": 1, "x": 120.5, "y": 90.25, "name": "Вход", "type": "entrance" }
  ],
  "edges": [
    { "from": "1_01", "to": "1_02", "weight": 6.5, "type": "corridor", "bidirectional": true }
  ],
  "restrictedAreas": [
    {
      "id": "restricted_demo_1",
      "floor": 1,
      "reason": "Серая зона закрыта для прохода.",
      "reasonEn": "The grey area is closed to traversal.",
      "polygons": [[{"x": 610, "y": 95}, {"x": 766, "y": 95}, {"x": 766, "y": 245}, {"x": 610, "y": 245}]]
    }
  ]
}
```

### Этажи (`floors`)

- `number`: уникальный номер этажа, совпадающий с `floor` в других записях.
- `title`: русская подпись переключателя.
- `mapAsset`: относительный путь к SVG внутри `assets`, например `floors/floor_3.svg`. PNG запрещён для карты.
- `width`, `height`, `viewBoxX`, `viewBoxY`: компоненты SVG viewBox.
- `metersPerUnit`: приблизительные метры на одну user-space единицу SVG.

При добавлении этажа добавьте SVG, запись этажа, узлы, помещения и GPS-якоря. Свяжите этаж с остальными графом через каждую реальную лестницу/доступный лифт. Новый этаж без межэтажных рёбер недостижим из остальных.

### Узлы (`nodes`)

- `id`: уникальная стабильная строка, например `2_08`.
- `floor`: существующий этаж.
- `x`, `y`: координаты SVG viewBox.
- `name`: подпись для переходной подсказки.
- `type`: `hallway`, `junction`, `stairs`, `elevator`, `door`, `entrance`, `exit` и т. п.
- `requiresAccessibility`: необязательный флаг; для узлов лифта — `true`.

### Рёбра (`edges`)

- `from`, `to`: ID существующих узлов.
- `weight`: конечная положительная приблизительная длина участка в метрах. Она учитывается при поиске пути и суммируется для отображаемой физической длины; предпочтения маршрута отдельно могут изменять стоимость выбора, но не это измерение.
- `type`: `corridor`, `stairs`, `elevator` или другой тип; межэтажный тип участвует в подсказке и предпочтениях маршрута.
- `bidirectional`: `true` для доступного прохода в обе стороны, `false` для одностороннего.
- `requiresAccessibility`: `true` для ребра лифта, недоступного стандартному маршруту. Включённая пользователем опция лифта уже существует в онбординге и настройках.

Соединяйте только реально проходимые участки. Не соединяйте близкие на рисунке точки через стену, закрытую серую область или актовый зал. На повороте рисуйте узел и два ребра, иначе линия маршрута может пройти сквозь стену. Проверьте однонаправленные связи с обеих сторон. Поле `requiresAccessibility: true` ставится на вертикальные ребра лифта; обычный маршрут их исключает. При включённом пользователем доступном маршруте лифт включается, а лестничные вертикальные ребра для той же пары этажей не используются. Остальные настройки предпочтений маршрута задают стоимость лестничных/лифтовых рёбер.

### Межэтажные лестницы и лифты

У одной реальной вертикальной связи создайте отдельный узел на каждом обслуживаемом этаже и межэтажное ребро между ними. Пример:

```json
{ "id": "1_stairs_west", "floor": 1, "x": 300, "y": 220, "name": "Западная лестница", "type": "stairs" }
{ "id": "2_stairs_west", "floor": 2, "x": 302, "y": 218, "name": "Западная лестница", "type": "stairs" }
{ "from": "1_stairs_west", "to": "2_stairs_west", "weight": 14, "type": "stairs", "bidirectional": true }
```

Координаты этих двух точек снимаются независимо на двух SVG. Не объединяйте разные лестничные клетки по сходству названий. Для лифта укажите `type: "elevator"`. Межэтажный маршрут выводится отдельными сегментами на планах этажей.

### GPS-якоря (`gpsAnchors`)

- `floor`, `id`: этаж и уникальный ID контрольной точки.
- `lat`, `lon`: измеренная широта/долгота WGS-84 в десятичных градусах.
- `x`, `y`: положение той же физической точки в системе координат SVG viewBox.

Для аффинной привязки используйте минимум три не лежащие на одной прямой GPS-точки, распределённые по плану. Текущие 8 anchors и их SVG-координаты демонстрационные; исходная картинка с углами колледжа не является геодезической съёмкой. Измерьте GPS/пиксельные соответствия на месте и проверьте результат в независимых контрольных точках. Внутренний GPS часто неточен; даже хорошее число accuracy не гарантирует точное положение.

GPS не определяет этаж. Приложение сохраняет этаж позиции отдельно; после межэтажного перехода пользователь выбирает план и при необходимости подтверждает этаж кнопкой «Я на этом этаже».

```json
      "name_en": "Computer Science Classroom",
      "number": "222",
      "floor": 2,
      "category": "classroom",
      "description_ru": "Кабинет информатики.",
      "description_en": "Computer science classroom.",
      "nodeId": "2_door_222",
      "x": 536.47555,
      "y": 213.5524,
      "svgElementId": "room_222",
      "svgElementIds": ["room_222"],
      "doorNodeId": "2_door_222",
      "doorNodeIds": ["2_door_222"],
      "polygons": [[{"x": 511.726, "y": 182.203}, {"x": 561.2251, "y": 182.203}, {"x": 561.2251, "y": 244.9018}, {"x": 511.726, "y": 244.9018}]],

```

### Особый случай: помещение 104

В текущем `rooms.json` запись 104 — актовый зал первого этажа. SVG-контур `room_104` и маркер `x/y` сохраняются для визуального отображения, но положение входа не подтверждено. Это **не** пункт назначения и **не** часть маршрута: не добавляйте для зала дверной узел или рёбра графа и не проводите через зал проход.

```json
{
  "id": "room_104",
  "name_ru": "Актовый зал",
  "name_en": "Assembly Hall",
  "number": "104",
  "floor": 1,
  "category": "common",
  "nodeId": null,
  "x": 683.3735,
  "y": 167.4141,
  "svgElementIds": ["room_104"],
  "route_available": false,
  "geometry_status": "display_only_non_routeable"
}
```

В полной записи также сохранены `polygons` и описание зоны. Наличие этого контура не отменяет `route_available: false`; при подтверждении доступного входа потребуется проверить его на плане и на месте, связать с узлом коридора и только затем включать маршрут.

Поля имени и описания локализованы (`name_ru/name_en`, `description_ru/description_en`). `number` — строка или `null`, `floor` — этаж, `category` — `classroom`, `laboratory`, `administrative`, `medical`, `common` либо `entrance`. `nodeId` — целевой узел двери/входа того же этажа; `x/y` — позиция отображаемого маркера в SVG и сами по себе не задают дверной проём. У непроверенного помещения `x/y` можно оставить `null`, `route_available` поставить в `false`, а `geometry_status` поясняет причину. `aliases_ru/aliases_en` поддерживают имена, номера и транслитерацию; поиск допускает частичное совпадение. `polygons` поддерживает несколько частей одного помещения, например кабинеты 202 и 230. `Room.requiresAccessibility` — свойство записи помещения (например, лифта); доступность маршрута и исключение лифтовых рёбер определяются одноимёнными полями узлов/рёбер `navigation_graph.json`, а не наличием контура помещения.

Категория личной папки избранного хранится отдельно в Room; не смешивайте её с категорией помещения. После добавления записи проверьте русский и английский поиск, алиас/транслитерацию, подсветку всех контуров и доступность маршрута.

## 7. Проверка JSON и карт

Перед сборкой сначала выполните `python3 tools/validate_indoor_data.py`, затем проверьте:

1. Убедитесь, что в `app/src/main/assets/floors/` лежат только ожидаемые `.svg`. Валидатор проверяет каталог из 34 утверждённых номеров, RU/EN-поля, SVG ID, viewBox, достижимость, закрытые зоны и пересечения рёбер коридоров с контурами помещений.
2. Проверьте JSON-синтаксис и отсутствие висячих запятых.
3. Сверьте SVG `viewBox` с `width/height/viewBoxX/viewBoxY` в JSON.
4. Проверьте границы всех x/y, существование `nodeId`, `edge.from/to`, уникальность ID и совпадение этажей.
5. Проверьте, что вес ребра конечен и положителен; убедитесь, что есть реальные пути к каждому этажу.
6. Выполните `./gradlew testDebugUnitTest`, `./gradlew assembleDebug`, установите APK и проверьте план/маршрут на двух этажах.
7. Пройдите каждый маршрут на месте с ответственным за здание; особо проверьте узел `1_01`, двери, лестницы и лифты.

`IndoorRepository` валидирует JSON и сверяет размеры viewBox SVG до показа карты; ошибка загрузки выводится на экран с кнопкой повтора. При замене файла сначала измерьте и перенесите координаты заново, затем обновите docs/этаж.

## 8. Производительность и большие SVG

- Оставляйте SVG вектором. Не растрируйте план и не вкладывайте фоновые PNG внутрь SVG.
- Перед добавлением удалите неиспользуемые скрытые слои, растровые эскизы, лишние метаданные и пустые группы; сохраните нужные ID.
- Упрощайте чрезмерно плотные кривые, не объединяя все элементы в один path: отдельные ID позволяют подсвечивать комнаты.
- Используйте локальные цвета/простые заливки; проверьте `filter`, маски, шрифты и CSS — AndroidSVG поддерживает не весь набор возможностей браузерного SVG.
- Если файл очень велик, разделите декоративные слои по допустимой архитектуре и измерьте загрузку/отрисовку на слабом Android-устройстве. Сначала оптимизируйте число узлов и кривых, а не переводите план в PNG.
- Обновляйте SVG только вместе с проверкой viewBox и всех GPS/комнатных/графовых координат.

## 9. Настройки, Room и ProGuard

Пользовательские настройки живут в Preferences DataStore и отдаются UI как Flow/StateFlow. Изменения темы, масштаба, единиц, GPS-порога и маршрута применяются без перезапуска. Избранное, пользовательские папки, история и сохранённые маршруты — отдельные Room-таблицы.

Для изменения схемы базы увеличьте `@Database(version=...)`, создайте явный `Migration(old,new)`, обновите DAO/Entity, протестируйте миграцию существующей базы и оставьте `exportSchema=true`. Не используйте `fallbackToDestructiveMigration()` для пользовательских данных. Схемы Room размещаются в `app/schemas/` при Gradle-сборке; сохраняйте их в контроле версий после появления.

Release сейчас собран с отключённой R8-минификацией. Если включаете `isMinifyEnabled`, проверьте `app/proguard-rules.pro`, сохраните модели/поля Gson и аннотации Room, соберите minified APK и проверьте JSON, миграции и SVG-ID-подсветку. Подробный APK-гайд: [`BUILD_APK_RU.md`](BUILD_APK_RU.md).
