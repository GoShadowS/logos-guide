# Разметка SVG-карт и проверка геометрии помещений

Документ описывает текущие Android-ресурсы и безопасное обновление разметки. В APK рендерятся только SVG-файлы; PNG-планы в `maps_and_design/` используются исключительно как справочные изображения.

## Авторитетные записи и ограничения текущих планов

`app/src/main/assets/rooms.json` содержит **47 записей**: 30 физических помещений из утверждённого списка (34 номера, потому что 141/142/147/159/160 — одна «Учебная часть» с одним входом) и 17 вспомогательных помещений/переходов. Номера 141, 142, 147, 159 и 160 находятся в `aliases_ru/aliases_en` одной записи `room_education_department`; они не создают пять отдельных дверей.

Отдельные записи и контуры поддерживаются независимо: 144 ожидает два подтверждённых смежных полигона; 202 выделяет кабинет и лаборантскую; 230 — электрорадиомонтажную и лаборантскую; у 225 план повторяет номер у практического помещения, поэтому связанный дополнительный контур помечен на проверку.

| Запись | Состояние данных |
|---|---|

| 141/142/147/159/160 | Одна физическая зона и один маршрут; точку входа необходимо подтвердить на месте. |

| 225 | Основная лаборатория и связанное подписанное на плане практическое помещение подсвечиваются вместе; проверить, относятся ли оба контура к одной записи. |

Отсутствие геометрии — явный статус данных, а не пропуск записи. Для такой комнаты в `rooms.json` оставляйте `x: null`, `y: null`, `polygons: []`, `route_available: false`, `nodeId: null` и поясняющий `geometry_status`. После подтверждения в здании добавьте реальные SVG-контуры и дверь, затем включите маршрут.

## ID в SVG

Стабильные ID назначаются элементам геометрии, не тексту подписи:

- помещение: `room_104`, `room_202_main`, `room_202_lab_assistant`, `room_230_main`, `room_230_lab_assistant`;
- дверной маркер/проём: `door_202`, `door_202_lab_assistant`, `door_230_main`;
- закрытая зона: `restricted_auditorium_2`.

В текущих app-копиях ID исправлены по элементам SVG. Утверждённые двери на плане размечены `door_*`; предполагаемые входы без явного дверного символа **не подменяются** новыми синими маркерами: например, для 104, учебной части и 207 в графе есть узлы с `geometry_status: "door_to_verify"` у комнаты.

`room_educational_department` соответствует объединённому физическому контуру учебной части; не назначайте ему пять раздельных входов. У лифта ID `room_lift_1` / `room_lift_2`, у лестничных клеток — отдельные `room_stairs_*`. На втором этаже серый блок актового зала/смотровой размечен `restricted_auditorium_2`; приложение не создаёт в нём ни комнатного маршрута, ни графовых узлов. Соседние серые технические фрагменты также внесены в `restrictedAreas`.

Если одно помещение состоит из нескольких раздельных `<rect>`, `<polygon>` или `<path>`, каждому элементу задайте **свой ID**, перечислите их в `svgElementIds`, а отдельные проверенные контуры храните в `polygons: [[[x,y], ...], ...]`-образной JSON-структуре с объектами `{"x":..., "y":...}`. Одного `svgElementId` недостаточно для кабинетов 144/202/225/230.

## Пошаговая разметка в Inkscape

1. Создайте резервную копию `app/src/main/assets/floors/floor_N.svg` и откройте SVG в Inkscape. Не используйте PNG как подложку для вычисления JSON-координат.
2. Откройте **Объект → Объекты** (Object → Objects) или **Редактор XML**. Убедитесь, что выбрана фигура стены/помещения, а не подпись, фон, маска или маркер пользователя.
3. Выберите один реальный контур помещения. Через **Object Properties / Свойства объекта** задайте ID без `#`, пробелов и кириллицы, например `room_232`. ID должен быть уникальным в пределах файла.
4. Для составного помещения проставьте отдельные ID всем реальным частям: например `room_144_part_a` и `room_144_part_b`. Не объединяйте смежные области только потому, что у них похожая заливка; сначала подтвердите назначение у ответственного за здание.
5. Отдельно выберите геометрию двери/проёма на доступной стороне коридора и задайте `door_<номер>` либо `door_<назначение>`. Цвет штриха сам по себе не доказывает, что это дверь; сверяйте с планом и на месте. Синяя линия около неизвестных зон «1»/«2» не считается доказательством частей кабинета 144.
6. Для закрытого серого участка задайте `restricted_<описание>`, внесите его контур в `navigation_graph.json.restrictedAreas` и убедитесь, что внутри нет узла и ребра маршрута.
7. Сохраните SVG без перемещения, поворота, обрезки страницы и изменения `viewBox`. Не превращайте план в PNG. Проверьте, что нужные ID сохранились в XML.
8. Извлеките геометрию и проверьте границы командой ниже. Сравните результат с планом, а маршрутные двери/узлы проверьте в приложении и на месте.

```bash
python3 tools/extract_svg_geometry.py app/src/main/assets/floors/floor_1.svg --strict
python3 tools/extract_svg_geometry.py app/src/main/assets/floors/floor_2.svg --strict
python3 tools/validate_indoor_data.py
```

Скрипт читает `<rect>`, `<polygon>` и закрытые `<path>`, преобразует вложенные `matrix/translate/scale/rotate/skew` к корневой SVG-системе координат, печатает bbox и точки. Кривые Безье выдаются как аппроксимация и годятся для проверки контура, но окончательные точки нужно визуально проверить и хранить явно в JSON. JSON-координаты берутся только в user-space SVG `viewBox`, не из размеров PNG/экрана.

## Создание маршрутов и доступность

1. Сначала поставьте узлы коридора, поворотов и лестничных площадок. Узел двери располагайте на доступной стороне проёма; сам маршрут к помещению заканчивается на дверном узле того же этажа.
2. Связывайте узлы рёбрами только по открытому пути. Линия между близкими точками не должна пересекать стену, комнату, закрытую серую зону или актовый зал. Не прокладывайте рёбра через observation room.
3. Межэтажный переход каждой конкретной лестницы связывает пару узлов с одним `stairsGroup`. Лифт имеет два этажных узла и вертикальное ребро `type: "elevator", requiresAccessibility: true`.
4. По умолчанию лифт исключён из маршрута. Опция уже выбрана в онбординге и доступна в настройках; при её включении граф использует лифт вместо лестничного перехода для той же пары этажей. Не добавляйте второй переключатель.
5. Для быстрого действия «Ближайший туалет» записи имеют `role: "restroom"`; для «Ближайшая лестница» — `role: "stairs"`. Положение пользователя должно быть известно (GPS или ручная точка).
6. Для исключённых мест добавляйте `restrictedAreas` с полигоном по SVG. Код дополнительно не позволяет ставить ручную точку или начинать маршрут из закрытого полигона; проверка графа не допускает узлы внутри него.

Узел `1_01` главного входа имеет предварительные координаты `x=576.54`, `y=240.96` в viewBox первого этажа. Обязательна полевая проверка положения дверного проёма, доступности пути и связей. Сами координаты коридоров и часть дверных точек также являются ориентировочными до проверки. Не заявляйте, что маршрут уже прошёл натурное тестирование.

## Сборка APK

Откройте Android-проект в Android Studio с JDK 17 и Android SDK 34, дождитесь Gradle Sync и выполните `./gradlew testDebugUnitTest` и `./gradlew assembleDebug`. Подробные шаги установки Android Studio, настройки SDK, запуска на устройстве и получения APK: [`BUILD_APK_RU.md`](BUILD_APK_RU.md). В текущем рабочем контейнере JDK отсутствует, поэтому компиляция и APK здесь не подтверждены.
