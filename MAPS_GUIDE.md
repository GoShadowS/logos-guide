# Как устроены и как править планы этажей

Приложение показывает **только внутренние планы корпуса** — внешней карты улиц нет.
По пользовательским контрольным точкам GPS уже геопривязан к каждому этажу; входящая
геопозиция отображается на выбранном плане с кругом точности. GPS внутри помещений
может быть неточным и не определяет этаж.

План этажа — это настоящий SVG-файл из папки `Map/` в корне репозитория. Он рисуется
как есть (`react-native-svg`), а поверх него приложение размещает нажимаемые области
по прямоугольникам помещений и маркеры отдельных POI. Выбранная комната подсвечивается;
маршрут рисуется поверх плана.

---

## 0. Что сейчас в проекте

| Этаж | Файл плана | Копия в приложении | Масштаб | Холст (viewBox) |
|---|---|---|---|---|
| `main-1` — 1 этаж | `Map/map1lower.svg` | `assets/images/maps/plan_main_floor_1.svg` | 10 ед. = 1 м | 758 × 552 |
| `main-2` — 2 этаж | `Map/map2lower.svg` | `assets/images/maps/plan_main_floor_2.svg` | 10 ед. = 1 м | 767 × 561 |

Связь этажа с файлом задаётся в `src/data/floors.json`:

```json
{
  "id": "main-1",
  "buildingId": "main",
  "level": 1,
  "width": 758,
  "height": 552,
  "unitsPerMeter": 10,
  "realPlan": "map1lower",
  "planFile": "plan_main_floor_1.svg"
}
```

| Поле | Зачем |
|---|---|
| `width` / `height` | должны **точно** совпадать с `viewBox` плана — иначе маркеры «поедут» |
| `unitsPerMeter` | масштаб этажа: сколько единиц viewBox в одном метре (влияет на расстояния и время в пути) |
| `realPlan` | имя файла плана в `Map/` без расширения |
| `planFile` | куда `npm run assets` копирует план внутри `assets/images/maps/` |
| `outline` | SVG-путь внешнего контура здания |
| `background` | цвет вне контура здания |
| `areas` | проходимые зоны: коридоры, холлы, лестничные клетки (`kind`: `corridor`, `hall`, `stairs`) |

---

## 1. Система координат

* Каждый этаж — свой «холст» `width × height` в единицах viewBox.
* Начало координат — **левый верхний угол**, ось Y направлена вниз (как в SVG).
* Координаты в JSON — те же числа, что и в SVG плана.

Чтобы узнать координаты объекта на плане:

* **Figma** — выделите объект, справа будут `X`, `Y`, `W`, `H`;
* **Inkscape** — `Ctrl+Shift+X` (XML-редактор) или панель координат;
* **любой SVG** — откройте файл текстом и посмотрите `x`, `y`, `width`, `height` прямоугольников.

## 2. Аудитории (`src/data/rooms.json`)

```json
{
  "id": "main-2-240",
  "buildingId": "main",
  "floorId": "main-2",
  "number": "240",
  "type": "classroom",
  "x": 620, "y": 300, "w": 96, "h": 72,
  "door": { "x": 668, "y": 300 },
  "label": "240",
  "name": { "ru": "Аудитория 240", "en": "Room 240" },
  "aliases": ["240", "кабинет 240"]
}
```

Обязательные поля:

* `id` — уникальный идентификатор;
* `floorId` — этаж из `floors.json`;
* `x, y, w, h` — прямоугольник помещения в единицах плана;
* `door` — точка двери **на границе помещения**, обращённой к проходимой зоне:
  маршрут заходит в помещение именно через неё;
* `type` — тип точки (см. `src/theme/poiTypes.js`): `classroom`, `lab`, `office`,
  `library`, `cafeteria`, `toilet`, `wardrobe`, `medical`, `hall`, `stairs`,
  `elevator`, `entrance`, `security`, `vending`.

Необязательное, но полезное:

* `label` — короткая подпись на плане (полное название часто не влезает);
* `number` — номер: по нему работает поиск («236»);
* `aliases` — дополнительные слова для поиска;

> ⚠️ Если `door` не на границе с коридором, маршрут до помещения не построится.
> Проверка: `npm test` и `npm run validate` — оба должны быть зелёными.

Отдельные точки (кулер, охрана, банкомат…) описываются так же в `src/data/poi.json`
(ключ `pois`), только вместо прямоугольника — одна точка `x, y`.

## 3. Замена или добавление плана

1. Положите новый SVG в `Map/` (например, `Map/map3lower.svg`).
2. `npm run assets` — скрипт скопирует планы из `Map/` в `assets/images/maps/`
   по полям `realPlan` → `planFile` (а также перегенерирует иконки, логотип и splash).
3. Добавьте этаж в `src/data/floors.json`: `width`/`height` возьмите из `viewBox`
   файла, укажите `unitsPerMeter`, `realPlan`, `planFile` и проходимые зоны `areas`.
4. Опишите помещения в `rooms.json` и связи между этажами в `graph.json`.
5. Запустите `npm run validate` и `npm test`.

Проверить координаты и двери по картинке помогают инструменты разработчика
(нужен `sharp`, он уже в devDependencies):

| Команда | Что делает |
|---|---|
| `node tools/_extract_rooms.js <svg> <out.json>` | цветовая сегментация плана → список прямоугольников помещений |
| `node tools/_blue.js <svg> [минПлощадь]` | находит синие элементы плана (двери, иконки) с координатами |
| `node tools/_ascii.js <svg> <x0> <y0> <x1> <y1> [шаг]` | текстовый дамп региона: `.` фон, `B` комната, `#` стена, `G`/`D` серые зоны, `+` синие элементы |
| `node tools/_crop.js <svg> <out.png> <x0> <y0> <x1> <y1> <zoom>` | сохраняет увеличенный фрагмент плана картинкой |

## 4. Лестницы и лифты (`src/data/graph.json`)

```json
"verticalLinks": [
  {
    "kind": "stairs",
    "a": { "floorId": "main-1", "x": 578, "y": 124 },
    "b": { "floorId": "main-2", "x": 585, "y": 126 }
  }
]
```

* `a` и `b` — одна и та же лестница на соседних этажах (координаты могут немного
  отличаться, если планы этажей размечены со смещением);
* обе точки должны попадать в **проходимую зону** своего этажа — это проверяет
  `npm run validate`;
* `kind` — `stairs` или `elevator`; от этого зависит текст инструкции
  («по лестнице» / «на лифте»).

Других видов связей в приложении нет: переходов с улицы не существует, потому что
карты улицы нет.

## 5. Параметры навигации (`graph.json`)

| Параметр | Значение | Смысл |
|---|---|---|
| `cellSize` | 10 | размер ячейки сетки проходимости в единицах плана |
| `walkSpeedMps` | 1.3 | скорость пешехода, м/с (≈4,7 км/ч) |
| `stairSeconds` | 25 | «плата» за переход между этажами, секунды |
| `wallPenalty` | 3 | штраф за движение у стены (маршрут идёт по центру коридора) |

Масштаб (`unitsPerMeter`) задаётся у каждого этажа в `floors.json`, а не здесь.

Сетка строится в `src/services/graph.js`: проходима ячейка, попадающая в коридор,
холл, лестницу, лифт или вестибюль. Помещение проходимо только по отрезку
«дверь ↔ центр», поэтому маршрут не прорезает аудитории.

## 6. Иконки

Эмодзи в приложении не используются — только векторные иконки
`MaterialCommunityIcons` (пакет `@expo/vector-icons`). Иконки показываются у отдельных
точек POI и в карточках; помещения на плане выбираются прозрачными областями,
а выбранная комната подсвечивается (`src/components/RoomHitArea.js`). Цвета и глифы
POI задаются в `src/theme/poiTypes.js`.

`npm run validate` проверяет, что каждое имя глифа действительно существует
в шрифте MaterialCommunityIcons и что в коде и переводах не осталось эмодзи.

## 7. GPS-геопривязка (`src/data/gps-calibration.json`)

В файле находятся контрольные точки, полученные с отмеченных пользователем планов.
Каждая запись связывает широту/долготу WGS84 с точкой `x/y` того же физического места
в SVG. Сейчас на каждом этаже по четыре точки. Они не должны быть коллинеарными;
при замене или повороте плана калибровку нужно выполнить заново.

`src/services/geolocation.js` проецирует координаты GPS в локальные метры и по точкам
строит аффинное преобразование в координаты viewBox методом наименьших квадратов.
Круг вокруг синей точки показывает заявленную точность телефона. GPS-разрешение
запрашивается после нажатия «Моё местоположение» или «Начать маршрут»; используется
foreground-доступ, без фонового слежения и без сетевых карт. При смене экрана подписка
останавливается.

Если GPS-точка с точностью до 20 м попадает в область плана и находится не дальше
примерно 12 м от прохода, она может стать началом маршрута. Иначе маршрут строится
от главного входа. Пользователь выбирает этаж вручную: GPS без отдельного датчика
не определяет этаж и внутри корпуса может давать большую погрешность.

После изменения геопривязки проверьте `npm run validate` и `npm test` — тесты
проверяют все контрольные точки и ошибку калибровки.

## 8. Проверка после правок

```bash
npm run validate   # геометрия, двери, viewBox планов, локализация, иконки и GPS-точки
npm test           # поиск, GPS-геопривязка и маршруты (в том числе «туда-обратно»)
npm run smoke      # запуск реальной веб-сборки в jsdom: карта, GPS-кнопка, зум, тема, поиск
npm run check      # всё сразу
```

`npm run validate` дополнительно следит, чтобы не вернулись данные расписания,
QR-сканер, Яндекс.Карты, этаж `campus`, блок `config.campus` и `extra.campusCenter`.
Вкладка «Расписание» остаётся только пустой визуальной заглушкой без данных. GPS допускается только
для локального определения местоположения и не добавляет внешнюю карту. Валидатор
проверяет GPS-разрешения и не менее трёх неколлинеарных точек на каждом этаже.

Дымовой тест (`tools/smoke-web.js`) сам собирает веб-бандл, если его нет:

```bash
npm run smoke                       # сборка + запуск в jsdom
node tools/smoke-web.js /tmp/export # проверить уже собранную папку
```

Он реально запускает приложение и «нажимает» кнопки: приближает карту, выбирает
помещение нажатием по его области, строит маршрут, переключает тему и печатает
в поиске. GPS-разрешение в web smoke не запрашивается: для него нужна реальная
поддержка геолокации браузером и безопасное соединение HTTPS.
