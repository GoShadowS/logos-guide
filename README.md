# ЛОГОС: Путеводитель

Офлайн-навигатор по учебному корпусу колледжа **АНО ПО «Технический колледж "Логос"»**.
Android + iOS + web, одна кодовая база на **React Native (Expo SDK 55)**.

Карта в приложении — это поэтажные SVG-планы из `assets/images/maps/`
(`plan_main_floor_1.svg` и `plan_main_floor_2.svg`). Приложение рисует их как есть,
а поверх добавляет прозрачные области нажатия по помещениям, линию маршрута и
пошаговые подсказки. Выбранное помещение подсвечивается и подписывается. Данные,
планы и переводы лежат в репозитории.

> Репозиторий: <https://github.com/GoShadowS/LOGOS-Guidebook>
> Дизайн-макеты: [`Design/`](../Design)

## Возможности

| Раздел | Что реализовано |
|---|---|
| **Планы этажей** | SVG-планы двух этажей корпуса. Панорамирование, pinch-зум, двойной тап, кнопки «+» / «−» / «вписать», переключение этажа. Кабинеты нажимаются прямо на плане и подсвечиваются при выборе. |
| **Поиск** | По номеру («236», «119»), названию («Столовая», «Библиотека») и алиасам. Быстрые категории, история поиска и **голосовой ввод** (`expo-speech-recognition`). |
| **Навигация** | Маршрут по корпусу и между этажами: A\* по сетке проходимых зон, пошаговые инструкции, расстояние и время. GPS-позиция отображается на плане и может стать началом маршрута при достаточной точности. Опорные точки заданы отдельно для каждого этажа; этаж GPS автоматически не определяет. |
| **Точки интереса** | Аудитории и лаборатории, кабинеты, медпункт, столовая, библиотека, туалеты, гардероб, пост охраны, входы и вестибюль, лифты и лестницы. |
| **Оформление** | Светлая, тёмная и системная темы — переключаются **мгновенно**, без перезапуска. В тёмной теме план карты автоматически затемняется. Русский и English, язык подхватывается из системы. |
| **Иконки** | Никаких эмодзи: только векторные глифы `MaterialCommunityIcons`. |
| **Избранное** | Закладки на аудитории и места (AsyncStorage). |
| **Данные** | Планы, помещения, GPS-калибровка и переводы локальны; настройки и избранное хранятся в AsyncStorage. Геопозиция запрашивается только после нажатия кнопки и обрабатывается на устройстве. |

## Быстрый старт

```bash
cd logos-guide
npm install
npm start          # dev-сервер Expo
```

Дальше:

* **телефон** — отсканируйте QR-код из терминала камерой (нужно приложение
  [Expo Go](https://expo.dev/go));
* **браузер** — `npm run web`;
* **сборка APK/IPA** — см. [`BUILD.md`](BUILD.md).

| Инструмент | Версия |

| npm | 10+ |
| Expo SDK | 55 (React Native 0.83, React 19.2) |

| iOS | 15.1+ |

## Как это работает

### Карта

`MapCanvas` показывает SVG-план этажа внутри жеста-контейнера
(`react-native-gesture-handler`) и масштабирует его анимированным слоем
`react-native-reanimated`. Все вычисления зума — ворклеты, они выполняются
в UI-потоке, поэтому pinch идёт плавно, а кнопки «+»/«−» вызывают те же ворклеты
через `runOnUI`. Масштаб ограничен 0.75×…6×, сдвиг — пределами плана, фокус зума
сохраняет точку под пальцем.

### Навигация

1. **Сетка проходимости** (`src/services/graph.js`) строится из `floors.json`
   с шагом `cellSize` (10 единиц плана = 1 м при `unitsPerMeter: 10`).
   Проходима ячейка, попадающая в коридор, холл, лестницу, лифт или вестибюль.
   Помещение проходимо только по отрезку «дверь ↔ центр» — маршрут не прорезает
   аудитории, а заходит через дверь. Штраф у стены (`wallPenalty`) держит маршрут
   в центре коридора.
2. **A\*** (`src/services/pathfinding.js`) ищет путь с учётом межэтажных связей из
   `graph.json` (лестницы и лифты). Путь упрощается (Дуглас—Пекер) и превращается
   в пошаговые инструкции с поворотами, переходами между этажами, расстоянием
   и временем в пути.
3. **GPS-положение** (`src/services/geolocation.js`) переводит WGS84-координаты
   в X/Y выбранного этажа по локальной аффинной калибровке из
   `src/data/gps-calibration.json`. Точка и круг точности рисуются прямо на SVG;
   при точности до 20 м и близости к проходу GPS может стать началом маршрута.
   Разрешение запрашивается после нажатия «Моё местоположение» или «Начать маршрут»;
   шаги остаются ручными из-за погрешности GPS. GPS не определяет этаж и не заменяет
   внешнюю карту; поэтажный план выбирается вручную.

### Тема и язык

* Тема `system / light / dark` хранится в AsyncStorage и применяется через
  React-контекст — смена видна сразу на всех экранах, перезапуск не нужен.
* Язык `system / ru / en` определяется через `expo-localization`, откат — английский.
* Цвета бренда: электрик-синий `#1A18E0`, тёмный фон `#0B0B14`.

## Проверки

```bash
npm run validate   # данные, планы, двери, локализация, иконки
npm test           # поиск и маршруты
npm run smoke      # реальная сборка запускается в jsdom и «нажимает» интерфейс
npm run check      # всё сразу
```

Что делает дымовой тест (`tools/smoke-web.js`): собирает веб-бандл
(`expo export --platform web`), запускает его в jsdom и проверяет, что приложение
стартует без ошибок, показывает настоящий план 1 этажа, зум работает
(1× → 1.6× → 2.56× → обратно), тап по аудитории открывает карточку и строит маршрут,
тема переключается мгновенно, в поиск можно печатать, вкладок ровно четыре,
а эмодзи в интерфейсе нет.

`npm run validate` заодно следит, чтобы удалённое не вернулось: файлы расписания,
QR-сканера, Яндекс.Карт, этаж `campus`, `config.campus`, `extra.campusCenter`
и эмодзи в коде или переводах приводят к ошибке. Проверяются также наличие GPS-разрешений
и достаточное число неколлинеарных опорных точек для каждого этажа.

## Что нужно заменить перед публикацией

1. **Данные планировок** — встроенные планы этажей находятся в `assets/images/maps/`.
   При обновлении планов: положите исходные SVG в `Map/` (если они доступны),
   поправьте координаты в `rooms.json` и запустите `npm run check`
   (порядок действий — в [`MAPS_GUIDE.md`](MAPS_GUIDE.md)).
2. **Идентификаторы приложения** — `ios.bundleIdentifier` и `android.package` в `app.json`.
3. **Иконка и splash** — `assets/images/logo.png`, `assets/images/splash.png`
   (перегенерируются командой `npm run assets`).
4. **`extra.eas.projectId`** — при первой облачной сборке EAS подставит свой.

## Частые вопросы

**Приложение работает без интернета?**
Планы, данные, GPS-калибровка и переводы доступны офлайн. GPS запрашивается на устройстве после нажатия кнопки; положение показывается на выбранном этаже с кругом точности. GPS внутри здания может ошибаться и не определяет этаж, поэтому этаж пользователь выбирает вручную.

**Как добавить аудиторию?**
Добавьте объект в `src/data/rooms.json` (координаты `x, y, w, h` и точка `door`
на границе с коридором) — она сразу появится на плане, в поиске и в навигации.
Проверьте себя командой `npm run check`.

**Почему кнопка микрофона неактивна?**
Голосовой ввод работает там, где есть системное распознавание речи и выдано
разрешение на микрофон. На Android нужны сервисы Google, в браузере — поддержка
Web Speech API; иначе кнопка остаётся заблокированной, а обычный ввод работает.

**Можно ли добавить ещё один корпус или этаж?**
Да. Положите план в `Map/`, добавьте этаж в `floors.json` и связи в `graph.json` —
инструкция в [`MAPS_GUIDE.md`](MAPS_GUIDE.md).
