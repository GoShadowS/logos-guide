# Инструкции проекта для Codex и других агентов

## Назначение и структура

«ЛОГОС: Путеводитель» — нативное Android-приложение для навигации по колледжу на Kotlin, Jetpack Compose и Material 3. UI находится в `app/src/main/java/com/logos/navigator/ui/`; локальные помещения и граф маршрутов — в `app/src/main/assets/rooms.json` и `app/src/main/assets/navigation_graph.json`; исходные планы — в `maps_and_design/floors/`; `tools/generate_kotlin_floor_maps.py` создаёт производное Kotlin-отображение в `app/src/main/java/com/logos/navigator/ui/map/GeneratedFloorMaps.kt`.

## Проверенное состояние выпуска и перехода

- Целевая версия по плану пользователя — **разрабатываемая `1.0.1-release`**. APK, Git-тег и GitHub Release этой версии в проверенных источниках не найдены; не называй её выпущенной и не добавляй несуществующую ссылку.
- В снимке исходников `394361783557c5e578ec05b6a20fe40541bcf436` `app/build.gradle.kts` задаёт `1.1.0-release`, `versionCode 4` и `applicationId=com.logos.navigator`. Это конфигурация именно указанного снимка, а не подтверждение текущего состояния `main` или целевой пользовательской версии. Не меняй версию, versionCode, подпись, release-настройки, workflow или APK без отдельного прямого разрешения.
- APK вручную выпускает владелец проекта через Android Studio. Изменение или слияние исходников не является сборкой, подписью или публикацией APK; не обещай релиз и не создавай артефакты/теги/публикации.
- Опубликован единственный GitHub Release с тегом `release` и asset `logos-guide-1.0.0-opendoors.apk`; source tree тега задаёт `1.0.0-opendoors` / code 3 и не содержит updater. Удалённый APK не удалось получить для проверки его манифеста и сертификата. Различай план, Gradle, локальный APK и опубликованный Release.
- В checkout есть отдельный локальный `app/release/app-release.apk` с метаданными `1.1.0-release` / code 4. Извлечённый из него сертификат не сравнивался с сертификатом удалённого Release APK; без `apksigner verify` или обоих бинарников не делай вывод о причине удаления.
- Для будущего перехода обязателен порядок: сначала экспортировать JSON и проверить, что файл существует, открывается и сохранён вне закрытых данных приложения; если это не удалось — старую версию не удалять. Затем удалить старую версию; только после фактической публикации установить официальный APK `1.0.1-release`; импортировать JSON лишь после проверки совместимости importer-а конкретного APK. До удаления предупреди о риске потери избранного, истории, папок, маршрутов, настроек и других локальных данных. JSON включает категории, избранное, историю и сохранённые маршруты, но не настройки. Не обещай Android Backup и не выдумывай техническую причину обязательного удаления.
- Текущий importer принимает `schemaVersion` 1–2; source tag `release` экспортирует schema 2. Это статическая совместимость исходников, а не подтверждение переноса в APK `1.0.1` или тест на устройстве.
- Текущий Gradle задаёт `OPEN_DOORS=false` для новых Debug и Release; старые APK это не меняет.
- Используй один встроенный updater. Он проверяет GitHub `releases/latest`, автоматически не загружает APK, сравнивает только числовые компоненты `versionName`, не `versionCode`; при текущем nonnumeric tag `release` код может показать «Установлена последняя версия» без сравнения. Текущий `1.1.0-release` также посчитает `1.0.1-release` более старой. Не утверждай, что legacy `1.0.0-opendoors` может обновиться самостоятельно. Любое исправление updater — отдельный согласованный кодовый PR с тестами, не документационный PR.
- Имя приложения во всех пользовательских локалях, системной метке, заголовках, заставке и onboarding — строго `ЛОГОС: Путеводитель`. Не переводить его как `LOGOS: Guide`; официальное юридическое название колледжа, package ID, домен и репозиторий не переименовывать без причины.
- Для GPS считай отсутствующую оценку точности неизвестной, а не точной. Не разрешай по неизвестной/невалидной оценке автоматический прогресс маршрута, авто-переход этажа или прибытие; отображай оценку горизонтального радиуса, не `±`-гарантию. Новую логику GPS покрывай unit-тестами; не логируй и не сохраняй координаты без отдельной необходимости.
- Не добавляй Bluetooth-локацию, BLE-маяки, оборудование, Wi-Fi, сервер или сбор данных без отдельного разрешения и подтверждённой калибровки/координат опорных точек. Bluetooth-связь сама по себе не задаёт абсолютную позицию.
- Руководство пользователя должно описывать только найденные функции и данные; любые иллюстрации должны иметь alt text и явно помечаться как схемы, если это не скриншоты реально запущенного приложения.
- Корневой `CLAUDE.md` должен содержать ровно `@AGENTS.md` (официальный синтаксис импорта Claude Code). Не утверждай, что Claude Code импортировал этот файл, если реальная Claude Code-сессия не подтверждена.

## Правила изменений

- Следуй существующему Kotlin/Compose, MVVM, `StateFlow`, Room и DataStore-коду; новые UI-строки добавляй с русским и английским переводами в Android resources.
- Сохраняй фирменные цвета `#2F5FE8`, `#F3F6FB`, тёмный акцент `#8AA8FF`, шрифт Onest и исходный логотип `maps_and_design/logo.png`; не перерисовывай и не искажай логотип.
- Карта, каталог и маршрутизация должны оставаться нативными и офлайн. Внешняя карта/WebView не используются. Прямые сетевые запросы самого приложения обслуживают updater; Android speech recognizer и внешнее приложение, выбранное для передачи, могут иметь собственное поведение сети.
- В приложении запрещены расписание, календарь, QR-точки, QR-коды, QR-сканирование и связанные экраны, сценарии, кнопки, заглушки или демонстрационные данные. Не добавляй их и не переноси с сайта.
- Не добавляй игры, ИИ-помощника, чаты, Easter eggs, достижения, рейтинги и другие функции, не нужные для офлайн-навигации. Не выдумывай помещения, геометрию, граф маршрутов, POI, преподавателей или иные данные.
- Без необходимости не меняй ID помещений/узлов, SVG-геометрию, алгоритмы маршрутов, GPS, Room-схему и сохранённые данные, обновление приложения, подпись и release-настройки. Перед правками проверь `git status`, ветку, HEAD и diff; сохраняй существующие изменения.
- Не добавляй зависимости и сетевые вызовы без обоснованной необходимости. Не включай секреты, ключи и пароли в репозиторий.
- Для каждой завершённой задачи, включая аудит, создай Markdown-отчёт `logs/YYYY-MM-DD-slug.md` и добавь его в `logs/INDEX.md`; формат описан в `logs/README.md`. Записывай точные проверки и их результаты, недоступные проверки и причину, статус визуального просмотра и связанные PR/коммиты. Отделяй исторические CI-результаты от проверок нового diff. Не сохраняй сырые логи сборки или секреты.

## Проверки

Команды запускаются из корня репозитория:

- `./gradlew --no-daemon testDebugUnitTest` — unit-тесты Android-модуля;
- `./gradlew --no-daemon assembleDebug` — debug-сборка;
- `./gradlew --no-daemon assembleRelease` — release-сборка;
- `python3 tools/validate_indoor_data.py` — проверка JSON, SVG, каталога и связности графа;
- `python3 tools/generate_kotlin_floor_maps.py --check` — сверка сгенерированной карты;
- `git diff --check` — проверка diff на пробельные ошибки.

Перед сдачей запускай доступные проверки и явно сообщай о тех, которые не удалось выполнить. Не выдавай статический анализ за сборку, CI, тест на устройстве или проверку реального APK.

## Общение и отчётность

Отвечай пользователю по-русски, если он не попросил другой язык. В итогах отличай выполненные проверки от недоступных и не утверждай, что проверил UI на устройстве или сайт визуально, если этого не было.
